## ADR-001：使用 Canvas 而非 SVG 渲染

**日期**：2026-05-24
**状态**：已采纳

### 背景
需要渲染 ~2600 个矩形，需要高性能渲染方案。

### 决策
使用 Canvas 2D，采用双层架构（Main + Hover）。

### 理由
1. SVG 在 2000+ 元素时性能下降明显
2. Canvas 只重绘变化区域，性能更优
3. 双层分离避免 hover 时重绘所有矩形
4. progressive rendering（Top 200 先渲染）保证首屏 < 1.5s

## ADR-002：腾讯 API 作为主数据源

**日期**：2026-05-24
**状态**：已采纳

### 背景
东方财富 API 不可用，需要可靠的港股数据源。

### 决策
- 主数据源：腾讯（qt.gtimg.cn）
- 备用数据源：新浪（hq.sinajs.cn）
- akshare：用于获取股票列表（非实时数据）

### 理由
1. 腾讯 API 响应时间 ~0.08s
2. 新浪作为降级方案
3. 两者都经过验证可用

## ADR-003：使用 Nuxt 3 而非纯 Vue 3

**日期**：2026-05-24
**状态**：已采纳

### 背景
需要 SSR 能力和服务器端 API。

### 决策
使用 Nuxt 3。

### 理由
1. 内置 Nitro 服务器，API 路由开箱即用
2. SSR 支持 SEO
3. 与 Vercel 部署无缝集成

## ADR-004：颜色映射使用 Sigmoid 函数

**日期**：2026-05-24
**状态**：已采纳

### 背景
港股无涨跌停限制，极端涨跌幅（30%+）需要合理映射。

### 决策
使用 `normalized = 2 / (1 + e^(-change/10)) - 1`

### 理由
1. 线性映射会导致极端值压缩
2. Sigmoid 函数在中心区域敏感，两端平缓
3. 红涨绿跌，符合 A 股/港股习惯

## ADR-005：使用令牌桶算法限流

**日期**：2026-05-24
**状态**：已采纳

### 背景
腾讯/新浪 API 有频率限制。

### 决策
使用令牌桶算法，3 秒最小间隔。

### 理由
1. 防止被 API 封禁
2. Nuxt Nitro 单进程，进程级单例即可
3. 前端随机 jitter 避免惊群效应
